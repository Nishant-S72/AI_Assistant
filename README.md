# AI Chief-of-Staff POC

A production-ready proof-of-concept for an AI-powered communication assistant that helps manage inboxes, generate contextual replies, and handle customer communications with policy-based safety checks.

## Features

- 🤖 **Multi-LLM Support**: Works with OpenAI API or local Ollama instances
- 🔍 **RAG (Retrieval-Augmented Generation)**: Vector store with automatic Chroma/JSON fallback
- 🛡️ **Policy Engine**: Keyword-based safety checks with configurable rules
- 📊 **Audit Logging**: Complete audit trail with prompt storage and metrics
- 🎨 **Modern UI**: Next.js frontend with Tailwind CSS and Framer Motion
- 🐳 **Docker Compose**: Local Postgres, Redis, and optional Chroma
- ✅ **Tests & CI**: Unit tests, integration tests, and GitHub Actions

## Quick Start

### Prerequisites

- Node.js >= 18
- Docker and Docker Compose
- (Optional) Ollama for local LLM

### One-Command Setup

```bash
# 1. Clone and enter directory
cd ai-chief-of-staff-poc

# 2. Bootstrap everything
yarn bootstrap

# 3. Edit .env and set OPENAI_API_KEY (or configure Ollama)
# Then start dev servers
yarn dev
```

The bootstrap script will:
- ✅ Check Docker installation
- ✅ Create `.env` from `.env.example`
- ✅ Start Docker services (Postgres, Redis)
- ✅ Install all dependencies
- ✅ Seed demo data (if `DEMO_SEED_TOKEN` is set)

Open http://localhost:3001 to see the app.

## Configuration

### Environment Variables

Copy `.env.example` to `.env` and configure:

```bash
# Required: Choose one LLM option
OPENAI_API_KEY=sk-...          # For OpenAI
# OR
USE_OLLAMA=true                 # For local Ollama
LLM_BASE_URL=http://localhost:11434
LLM_MODEL=llama2

# Vector Store (auto-detects)
VECTORSTORE_MODE=auto          # 'auto', 'chroma', or 'json'
CHROMA_BASE_URL=http://localhost:8000

# Optional
DEMO_SEED_TOKEN=your-secret-token
ADMIN_API_KEY=your-admin-key
LOG_LEVEL=info
MAX_PROMPT_TOKENS=8000
```

### Using Ollama (Local LLM)

1. Install Ollama: https://ollama.ai
2. Pull a model: `ollama pull llama2`
3. Set in `.env`:
   ```bash
   USE_OLLAMA=true
   LLM_BASE_URL=http://localhost:11434
   LLM_MODEL=llama2
   ```

The system will automatically fall back to OpenAI if Ollama is unreachable.

## Offline Local Demo Mode

Run the app **fully offline** with a local LLM and dummy inbox data. No internet or API keys required after initial setup.

### Prerequisites

1. **Install Ollama**:
   ```bash
   curl -fsSL https://ollama.com/install.sh | sh
   ```

2. **Pull a model** (recommended: `phi3` for speed, or `llama2` for quality):
   ```bash
   ollama pull phi3
   # OR
   ollama pull llama2
   ```

3. **Start Ollama** (if not running as a service):
   ```bash
   ollama serve
   ```

### Quick Start (Offline Mode)

```bash
# Run the local demo script
./scripts/run_local_demo.sh
```

This script will:
- ✅ Create `.env` with offline defaults
- ✅ Start Docker services (Postgres, Redis)
- ✅ Load dummy inbox from `/demo-inbox/` folder
- ✅ Start backend and frontend servers

Then visit **http://localhost:3001** to see:
- 🧠 **Offline Demo Mode** banner at the top
- 3 demo inbox threads (Lead Inquiry, Shipping Complaint, Meeting Request)
- AI-generated replies using your local LLM
- Simulated send actions (no actual emails sent)

### Offline Mode Features

- **Local LLM**: All AI suggestions generated by Ollama running on your machine
- **Dummy Inbox**: Pre-loaded threads from JSON files in `/demo-inbox/`
- **No Internet Required**: Works completely offline (except for Ollama)
- **Simulated Actions**: Send button shows "Reply sent (simulated)" toast
- **Local Storage**: Prompts and responses saved to `backend/storage/prompts_local/`

### Dummy Inbox Structure

The `/demo-inbox/` folder contains 3 JSON files:
- `lead_inquiry.json` - Bulk order inquiry for 200 vegan bags
- `shipping_complaint.json` - Delayed shipment complaint
- `meeting_request.json` - Partnership discussion request

Each file contains:
- Contact information
- Subject line
- Message thread (customer and assistant messages)
- Tags and priority

**Offline Mode** (default in `.env.example`):
```bash

LLM_MODEL=phi3
```

**Online Mode**:
```bash
USE_OLLAMA=false
```

### Using Chroma (Vector Store)

1. Start Chroma (if you have the Docker image):
   ```bash
   docker run -d -p 8000:8000 chromadb/chroma:latest
   ```
2. Set `VECTORSTORE_MODE=chroma` or leave as `auto` for auto-detection
3. If Chroma is unavailable, the system automatically falls back to JSON-based storage

## API Endpoints

### Messages
- `GET /api/messages` - List messages (filters: `?folder=all|leads|tasks`)
- `GET /api/messages/:id` - Get thread with contact and suggestion
- `POST /api/messages/:id/generate` - Generate AI suggestion
- `POST /api/messages/:id/send` - Send reply

### Admin
- `GET /api/admin/audit?limit=50` - View audit logs (requires `ADMIN_API_KEY`)
- `GET /api/admin/metrics` - Get metrics (acceptance rate, latency, etc.)

### Health
- `GET /api/health` - Health check with service status

## Development

### Adding a Policy Rule

Edit `backend/policy.json`:

```json
{
  "rules": [
    {
      "keywords": ["your", "keywords"],
      "action": "ESCALATE",
      "reason": "Your reason",
      "confidence": 0.9
    }
  ]
}
```

Reload rules by restarting the server or calling the reload endpoint.

### Updating Prompt Templates

Edit `prompts/assistant_template.md`. The template supports:
- `{{tone}}` - Tone (formal/warm/crisp)
- `{{contactName}}` - Contact name
- `{{contactCompany}}` - Company name
- `{{#retrievedContext}}...{{/retrievedContext}}` - Knowledge base context
- `{{#each threadMessages}}...{{/each}}` - Conversation history

### Changing Token Limits

Set `MAX_PROMPT_TOKENS` in `.env` (default: 8000). The prompt builder automatically truncates if exceeded.

## Troubleshooting

### Postgres not ready
```bash
docker compose ps
docker compose logs postgres
# Wait a few seconds and retry
```

### Chroma not reachable
The system automatically falls back to JSON storage. Check logs for:
```
[VectorStore] Auto-detected: JSON adapter (Chroma not available)
```

### Ollama connection failed
Check Ollama is running:
```bash
curl http://localhost:11434/api/tags
```
If unreachable, the system falls back to OpenAI (if API key is set).

### Seed script fails
Ensure `DEMO_SEED_TOKEN` is set in `.env` and matches the token used in the API call.

## Viewing Audit Logs

```bash

  http://localhost:3000/api/admin/audit?limit=50

# Get metrics
curl -H "Authorization: Bearer $ADMIN_API_KEY" \
  http://localhost:3000/api/admin/metrics
```

## Downloading Stored Prompts

Prompts are stored gzipped in `backend/storage/prompts/`:
```bash
# Decompress a prompt
gunzip backend/storage/prompts/suggestion-{id}.gz
cat backend/storage/prompts/suggestion-{id}
```

## Production Deployment

1. Set all required environment variables
2. Build: `yarn build`
3. Start: `yarn start`
4. Ensure Docker services are running or use managed Postgres/Redis
5. Configure reverse proxy (nginx/traefik) for frontend
6. Set up log rotation for audit logs

## Security Notes

- Never commit `.env` files
- Use strong `DEMO_SEED_TOKEN` and `ADMIN_API_KEY` in production
- Policy engine blocks sensitive content, but review all suggestions
- Audit logs may contain sensitive data - secure storage required
- Rate limiting recommended for production (add middleware)
